** +
/bisos.postgres/ makes PostgreSQL the *bedrock* of BISOS: the sole database, and a generic
layer on which other capabilities are built. Airflow, django-based packages and the other
capabilities that need a database converge on it, each as a *tenant*, so that many
capabilities can co-exist consistently on one host.

A tenant is a PostgreSQL role plus a database of the same name, owned by that role. It is
reached over the unix socket by peer authentication from the like-named OS account: no
password and no secret anywhere. The administrator is the =postgres= OS account that Debian
creates with the package.

*What this package provides*: the capability that installs the server and the client
development headers, and keeps the cluster running with =max_connections= of at least 200.
It authors *no* systemd unit: Debian's =postgresql.service= is used as is, and tenants'
units say =Requires=/=After= =postgresql.service=.

*Materialization*: the CBM leaf =sys/cbm/collective/bedrock/postgres/= points to
=postgres-cbs.pcs=, whose bundle is =postgres-sbom.pcs= alone. The CBM walker processes the
=bedrock= capabilityType before all other types.

*Not yet decided* (see the TODOs below and =AI-WorkPlan.org=): the interface through which a
consumer asks for its role and database, =pg_hba.conf= ownership, major-version upgrades,
backup, and adopting the already-running airflow tenant of this host.

*Clients*, layered: =psql= (the baseline, in every bedrock install); Emacs (=sql-mode=, org-babel
SQL, PGmacs) for Blee; DBeaver Community Edition as the optional GUI; and Microsoft's PostgreSQL
extension for VS Code, an accommodation for proprietary environments. The BISOS Platform is
edge-oriented and includes a desktop, so a GUI on a host is normal. The clients are a group sbom,
=dbClients-sbom.pcs= (=postgresql-client=, and DBeaver through =dbeaver-sbom.pcs=, a file of its own),
pulled in by =postgres-sbom.pcs= after the server steps; the group also stands alone, for a platform
that needs only clients (written, not yet run). DBeaver comes
from the vendor apt source, whose key is trusted on first use, and sends anonymous usage statistics
by default (switched off per user in its Preferences). Whether the VS Code extension can
use the unix socket with peer authentication is not confirmed.
